# Sonnet レビュー

順番は 実装 → このレビュー → PR 作成。**レビューが走っている間は PR を作らない。**

## 手順

1. `git status --short` と `git diff main...HEAD --stat` で対象を確かめる。未コミットの変更と未追跡ファイルも対象に含める
2. `Agent` を `model: "sonnet"`、`run_in_background: true` で起動し、下の依頼文を渡す。
   `{...}` は埋める。サブエージェントは会話の文脈を持たないので、意図と「あえてやっていないこと」は必ず書く
3. 完了通知を待つ。ポーリングしない。待つ間はレビュー結果に依存しない作業だけ進める
4. 指摘は鵜呑みにしない。挙げられた ファイル:行 と根拠のコードを自分で読み、成り立つものだけ採る
5. 本人には「採った指摘と直し方 / 採らなかった指摘と理由」を出す。直したら lint / typecheck / test を回し直す

## 依頼文

```
/Users/shingo/workspace/hand-made-agent のブランチ {branch} の差分をレビューしてください。ファイルは変更しないでください。

対象: `git diff main...HEAD`、未コミットの `git diff`、未追跡ファイル {files}。

背景: フレームワークを使わずに手で作るエージェント（hma）の練習用リポジトリ。CLAUDE.md と PLAN.md に作法と不変条件がある。
今回の変更: {何をなぜ変えたか}

意図的にやっていないこと（指摘不要）: {あえて残した穴。無ければ「なし」}

見てほしい点:
- 正しさ。既存の呼び出し元・似た実装（{比べるファイル}）と比べた抜けや誤り、例外時と後始末
- CLAUDE.md の不変条件（層の向き、権限は deny > allow > ask、種類の分からないツールを read 扱いしない等）を破っていないか
- 権限まわりを触っているならテストが足りているか
- README / docs/notes.md の記述がコードの挙動と食い違っていないか
- コメントは最小限・日本語というこのリポジトリの書き方から外れていないか

完了条件: 指摘を重要度順に並べて返す。各指摘に ファイル:行、何が起きるか（具体的な入力や状況）、根拠にしたコード箇所を書く。確証のないものは「未確認」と明記する。問題がなければ「指摘なし」と返す。
```
